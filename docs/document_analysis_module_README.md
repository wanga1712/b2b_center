# Модуль анализа документации закупок

## Обзор

Модуль анализа документации - это комплексная система для автоматического поиска и анализа документов закупок на предмет соответствия интересующим товарным позициям и требованиям заказчика.

## Функциональность

### Что делает модуль

1. **Автоматический поиск закупок** по заданным фильтрам
2. **Загрузка и распаковка документов** закупок
3. **Анализ содержимого документов** на предмет соответствия товарам
4. **Сохранение результатов анализа** в базу данных
5. **Управление очередью обработки** для оптимизации производительности

### Действия пользователя

#### 1. Настройка фильтров поиска (UI: `modules/bids/bids_settings_tab.py`)

- **ОКПД коды**: Выбор интересующих кодов продукции
- **Регион**: Географическая область поиска
- **Тип закупки**: Новые, выигранные, комиссионные
- **Стоп-слова**: Исключаемые из анализа слова/фразы
- **Стоп-фразы документации**: Исключаемые фразы в документах

#### 2. Запуск анализа (`modules/bids/widget.py`)

- Кнопка "Анализировать все" в интерфейсе
- Автоматический запуск фонового процесса

### Типы обрабатываемых файлов

#### Поддерживаемые форматы:
- **Excel файлы**: `.xlsx`, `.xls`, `.xlsm`
- **Word документы**: `.docx`, `.doc`
- **PDF документы**: `.pdf`
- **Архивы**: `.rar`, `.zip`, `.7z`

#### Структура обработки:
1. **Распаковка архивов** в временную директорию
2. **Парсинг файлов** с извлечением текстового содержимого
3. **Поиск совпадений** с товарами и пользовательскими фразами

## Используемые таблицы базы данных

### База данных: `tender_monitor`

#### Основные таблицы:

1. **`tenders`** - Основная информация о закупках
   - `id` - ID закупки
   - `registry_type` - Тип реестра (44fz, 223fz)
   - `tender_type` - Тип закупки (new, won, commission)
   - `external_id` - Внешний ID закупки
   - `title` - Название закупки
   - `initial_price` - Начальная цена
   - `final_price` - Итоговая цена
   - `region_id` - ID региона
   - `status_id` - Статус закупки

2. **`tender_document_matches`** - Результаты анализа
   - `id` - ID совпадения
   - `tender_id` - ID закупки
   - `registry_type` - Тип реестра
   - `product_name` - Найденное название товара
   - `score` - Оценка совпадения (0-100)
   - `matched_text` - Совпавший текст
   - `sheet_name` - Имя листа (для Excel)
   - `row`, `column` - Позиция в документе
   - `matched_keywords` - Совпавшие ключевые слова

3. **`tender_documents`** - Документы закупок
   - `id` - ID документа
   - `tender_id` - ID закупки
   - `url` - Ссылка на документ
   - `filename` - Имя файла
   - `file_type` - Тип файла

4. **`user_search_settings`** - Настройки поиска пользователя
   - `user_id` - ID пользователя
   - `region_id` - Выбранный регион
   - `category_id` - Выбранная категория
   - `okpd_codes` - Список ОКПД кодов

5. **`products`** - Каталог товаров для поиска
   - `id` - ID товара
   - `name` - Название товара
   - `category_id` - ID категории
   - `subcategory_id` - ID подкатегории
   - `manufacturer_id` - ID производителя

6. **`okpd_codes`** - Справочник ОКПД кодов
   - `code` - ОКПД код
   - `name` - Название

7. **`regions`** - Справочник регионов
   - `id` - ID региона
   - `name` - Название региона

8. **`stop_words`** - Стоп-слова для фильтрации
   - `word` - Стоп-слово

9. **`stop_phrases`** - Стоп-фразы документации
   - `phrase` - Стоп-фраза

### База данных: `commercial_db` (опционально)

Используется для загрузки расширенного каталога товаров, если требуется.

## Логика работы модуля

### 1. Фаза фильтрации закупок

```sql
-- Пример фильтра для новых закупок 44-ФЗ
SELECT r.id, r.external_id, r.title
FROM tenders r
LEFT JOIN tender_document_matches tdm ON r.id = tdm.tender_id
WHERE r.registry_type = '44fz'
  AND r.status_id = 1  -- Новые закупки
  AND r.region_id = ?  -- Фильтр по региону
  AND r.okpd_id IN (?) -- Фильтр по ОКПД
  AND tdm.id IS NULL   -- Не обработанные ранее
  AND NOT EXISTS (
      SELECT 1 FROM stop_words sw
      WHERE LOWER(r.title) LIKE '%' || LOWER(sw.word) || '%'
  )
```

### 2. Фаза загрузки документов

- **Предварительная загрузка** (`tender_prefetcher.py`):
  - Скачивание документов в фоне
  - Управление очередью по размеру файлов
  - Ограничение: не более 20 МБ на закупку

- **Обработка архивов** (`archive_processor.py`):
  - Распаковка RAR/ZIP/7Z
  - Рекурсивная обработка вложенных архивов
  - Фильтрация по расширениям файлов

### 3. Фаза анализа содержимого

#### Поиск товаров (`match_finder.py`):

1. **Подготовка паттернов поиска**:
   - Извлечение ключевых слов из названий товаров
   - Учет морфологии и синонимов

2. **Парсинг документов**:
   - **Excel**: `openpyxl` для чтения ячеек
   - **PDF**: `PyPDF2` или `pdfplumber` для извлечения текста
   - **Word**: `python-docx` для чтения документов

3. **Матчинг ключевых слов** (`keyword_matcher.py`):
   - Поиск точных совпадений
   - Учет расстояния Левенштейна
   - Взвешенная оценка совпадения

#### Пользовательские фразы:

- Дополнительный поиск по фразам пользователя
- Примеры: "инъектирование", "усиление", "гидроизоляция"

### 4. Фаза сохранения результатов

Сохранение в `tender_document_matches`:
- Только совпадения с оценкой > 50
- Группировка по товарам (лучшее совпадение)
- Сохранение метаданных совпадения

## Настройки и параметры

### Производительность

- **Максимальный размер файла**: 20 МБ на закупку
- **Количество воркеров**: 4 параллельных потока
- **Таймаут загрузки**: 120 секунд на файл
- **Батч размер**: 10 закупок за раз

### Качество поиска

- **Минимальная оценка совпадения**: 50
- **Максимальное количество совпадений**: 50 на документ
- **Учет стоп-слов**: Автоматическая фильтрация

### Логирование

- **Уровень логирования**: DEBUG для разработки, INFO для продакшена
- **Файл логов**: `.cursor/debug.log`
- **Формат**: NDJSON с метками времени

## Архитектурные особенности

### Асинхронная обработка

- **ThreadPoolExecutor** для параллельной обработки
- **Предварительная загрузка** для оптимизации I/O
- **Очередь по приоритету** (меньшие файлы обрабатываются первыми)

### Обработка ошибок

- **Graceful degradation**: Продолжение работы при ошибках
- **Повторные попытки**: Для сетевых ошибок
- **Логирование**: Детальные логи всех ошибок

### Масштабируемость

- **Батчевая обработка**: Групповая обработка закупок
- **Пейджинг**: Для больших объемов данных
- **Кэширование**: Результатов поиска и настроек
